# Комбинированное меню управления ботом

Дата: 2026-08-02

## Цель

Сейчас у бота 17 текстовых команд (`bot.py`), клавиатур нет вообще —
всё вводится руками, включая номера колёс для `/removewheel` и точные
имена каналов/слов для удаления. Нужно добавить inline-меню для
навигации и удаления по кнопке, не убирая текстовые команды (они
остаются основным способом добавления — ввести строку кнопками нельзя).

## Архитектура

- Новый модуль `wheelsparser/menu.py` — по образцу `active_report.py`:
  сборка inline-клавиатур, роутер callback'ов, in-memory undo-состояние.
- `wheelsparser/telegram_api.py`:
  - `_post_message`, `bot_send`, `background_bot_send` — добавляется
    необязательный параметр `reply_markup: dict | None`.
  - Новая `edit_message_text(chat_id, message_id, text, reply_markup=None)`
    — POST `/editMessageText`. Ошибку Telegram «message is not modified»
    (400) не логируем как сбой — это штатный случай при повторном тапе.
  - Новая `answer_callback_query(callback_id, text="", show_alert=False)`
    — POST `/answerCallbackQuery`. Вызывается на каждом обработанном
    callback'е, иначе кнопка у пользователя «крутится» до тайм-аута.
- `wheelsparser/bot.py`:
  - `bot_loop` дополнительно разбирает `update["callback_query"]`
    наравне с `update["message"]`, той же проверкой доверенного чата
    (`TELEGRAM_CHAT_ID`) — чужие/неизвестные callback'и молча
    игнорируются (как сейчас с неизвестными командами).
  - Новый `CALLBACK_HANDLERS: dict[str, Callable]` — роутинг по
    префиксу `callback_data` (аналог `COMMAND_HANDLERS`).
  - `BOT_COMMANDS` пополняется пунктом `/menu`.
- `wheelsparser/storage.py`: новая `unmark_wheel_removed(url) -> bool`,
  симметричная существующей `mark_wheel_removed` — снимает пометку
  ручного удаления колеса (нужна для отмены удаления через `/active`).

## Корневое меню `/menu`

Одно сообщение, разделы открываются через `editMessageText`
(сообщение не плодится), везде кнопка «← Назад»:

```
☰ Меню
┌────────────────────────┐
│ 📊 Находки              │
│ 📡 Каналы               │
│ 🎮 Twitch                │
│ 🔑 Слова                 │
└────────────────────────┘
```

- **📊 Находки** → кнопки: Колёса за N мин / Активные / Статус /
  Топ каналов — каждая просто вызывает существующий текстовый
  обработчик (`cmd_wheels`, `cmd_active`, `cmd_status`, `cmd_top`) и
  шлёт результат отдельным сообщением (не редактирует меню — вывод
  команд длинный и растёт).
- **📡 Каналы** → список `@channel ❌` (по одной кнопке-строке на
  канал), внизу «← Назад».
- **🎮 Twitch** → аналогично, `twitch.tv/channel ❌`.
- **🔑 Слова** → аналогично, `слово ❌`.

`/start` и `/help` получают дополнительную кнопку «☰ Меню» под
текстом (callback `m:root`).

Текстовые команды `/channels`, `/twitch`, `/words` тоже получают те
же кнопки ❌ под своим обычным ответом — не только через `/menu`.
`/active` и `/wheels` получают кнопки ❌ под каждой строкой колеса
(замена ручного ввода номера в `/removewheel`); текстовый
`/removewheel N` остаётся рабочим как есть.

## Callback-схема

`callback_data` ограничен 64 байтами и не гарантированно переживает
изменение списка между отрисовкой и тапом — схема выбрана так, чтобы
не превышать лимит и минимизировать последствия гонки:

| Значение | Смысл |
|---|---|
| `m:root` | корневое меню |
| `m:wheels` / `m:channels` / `m:twitch` / `m:words` | разделы |
| `ch:rm:<channel>` | удалить TG-канал (имя ≤32 байт — влезает целиком) |
| `tw:rm:<channel>` | удалить Twitch-канал (имя ≤25 байт) |
| `wd:rm:<idx>` | удалить слово по индексу в текущем снапшоте (слово может быть до 64 символов — целиком не влезает) |
| `rmw:<n>` | удалить колесо по номеру из нумерации `/active` (как сейчас `/removewheel N`) |
| `undo:channel` / `undo:twitch` / `undo:word` / `undo:wheel` | отменить последнее удаление в категории |

Для `wd:rm:<idx>`: если к моменту тапа `idx >= len(текущий список)`,
показываем тост «Список изменился — откройте /words заново» вместо
удаления не того элемента.

## Отмена удаления (окно 10 сек)

Один слот на категорию в памяти `menu.py`, под локом (тот же паттерн,
что `_last_active_numbers` в `active_report.py`):

```python
_last_deletion: dict[str, tuple[str, float]]  # категория -> (значение, время)
```

Новое удаление в категории перезаписывает предыдущий слот — это
undo «последнего действия», не полная история. После удаления в
ответе появляется кнопка «↩️ Отменить». В пределах 10 секунд тап
восстанавливает значение (для канала — без повторной сетевой
проверки `check_channel_preview`, он уже был известен рабочим; для
колеса — `storage.unmark_wheel_removed`). После истечения окна тап
по «Отменить» отвечает тостом с точной командой для ручного
восстановления (`/add @x`, `/addword x`, `/addtwitch x` или
уточнением про `/active`).

## Обработка ошибок

- Каждый обработанный callback обязательно закрывается
  `answer_callback_query` (успех — короткий тост или молча; ошибка —
  тост с причиной).
- `editMessageText` на «message is not modified» — не ошибка, просто
  no-op (пользователь дважды тапнул одну кнопку).
- Гонки по индексам (`wd:rm:<idx>`) — bounds-check с понятным
  сообщением, без исключений.
- Untrusted/неизвестные callback'и — молча игнорируются (без
  `answer_callback_query`), симметрично текущему поведению для
  неизвестных команд.

## Вне рамок

- FSM/пошаговый ввод текста через кнопки (добавление по-прежнему
  командой).
- Reply-клавиатура (постоянная нижняя панель) — не нужна поверх
  inline-дерева, решили на брейнсторминге.
- Подтверждение «Да/Нет» перед удалением — заменено на «Отменить»
  после факта.
