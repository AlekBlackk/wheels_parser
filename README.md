# WheelsParser

Отслеживает публичные Telegram-каналы (через `t.me/s/<channel>`, без Telegram API) и Twitch-чаты (анонимный IRC, без токенов и OAuth), находит ссылки `betboom.ru/freestream/...` и присылает их в Telegram. В Telegram ищутся ссылки и ключевые слова, в Twitch — только ссылки от стримера, модераторов, VIP и известных ботов.

Перед отправкой статус колеса проверяется через API BetBoom (`PRECHECK_WHEELS`) — завершившиеся не рассылаются. Находки хранятся локально, бот отвечает на команды.

## Запуск

Windows: установите Python 3.10+, скопируйте `env.example` в `.env`, заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, запустите `run.bat` — он сам создаст окружение и поставит зависимости.

Вручную:

```bash
python -m pip install -e .
python -m wheelsparser
```

Тесты — `python -m pytest`.

## Команды бота

Принимаются только из чата `TELEGRAM_CHAT_ID`.

| Команда | Действие |
|---|---|
| `/start` | Приветствие и краткая информация о боте |
| `/active` | Живые колёса за сегодня (сброс в 00:00 МСК) |
| `/removewheel <номер\|ссылка>` | Убрать колесо из `/active` до 00:00 МСК; номер — из последнего ответа `/active`; алиас `/delwheel` |
| `/wheels` | Колёса за последние `WHEELS_WINDOW_MINUTES` минут |
| `/status` | Статистика найденных ссылок |
| `/top [дней]` | Каналы по числу найденных колёс; период — `TOP_PERIOD_DAYS`, либо числом: `/top 7` |
| `/channels`, `/add @channel`, `/remove @channel` | Telegram-каналы (сохраняются в `channels.txt`) |
| `/twitch`, `/addtwitch channel`, `/removetwitch channel` | Twitch-каналы (`twitch_channels.txt`; принимается логин или ссылка `twitch.tv/логин`) |
| `/words`, `/addword слово`, `/removeword слово` | Ключевые слова (`keywords.txt`); `слово` — по границам слова с учётом окончаний, `*слово*` — по подстроке |
| `/help` | Список команд и текущие настройки |

## Настройки

Задаются в `.env` (шаблон — `env.example`). Пустое значение = значение по умолчанию.

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `TELEGRAM_BOT_TOKEN` | пусто | Токен бота |
| `TELEGRAM_CHAT_ID` | пусто | Чат для уведомлений и команд |
| `WHEELSPARSER_DATA_DIR` | `data/` | Каталог состояния: база, JSON, лог, lock |
| `WHEELSPARSER_CHANNELS` | встроенный список | Каналы через запятую. Только при первом запуске, пока нет `channels.txt`; дальше правда — файл и `/add`, `/remove` |
| `CHECK_INTERVAL` | `60` | Интервал проверки, сек (мин. 10) |
| `REQUEST_TIMEOUT` | `15` | Тайм-аут HTTP-запроса |
| `MESSAGES_PER_CHANNEL` | `50` | Сообщений на канал за проход |
| `CHANNEL_FETCH_CONCURRENCY` | `4` | Каналов опрашивается одновременно (было — строго по одному) |
| `MAX_SEEN_PER_CHANNEL` | `2000` | Максимум ID на канал |
| `MAX_RESULTS` | `5000` | Максимум записей истории в `wheels.db` (старые отбрасываются) |
| `WHEELS_WINDOW_MINUTES` | `10` | Окно `/wheels`, мин |
| `TOP_PERIOD_DAYS` | `30` | Период `/top` по умолчанию, дней |
| `ACTIVE_MAX_AGE_HOURS` | `20` | Макс. возраст колеса для `/active`, ч |
| `ACTIVE_CHECK_CONCURRENCY` | `3` | Потоков опроса API BetBoom при `/active` |
| `REALERT_COOLDOWN_MINUTES` | `30` | Кулдаун повтора по URL, мин |
| `EXPIRED_CACHE_TTL_SECONDS` | `120` | TTL кэша expired-статусов в precheck/`/active`, сек (не связан с `REALERT_COOLDOWN_MINUTES`) |
| `PRECHECK_WHEELS` | `true` | Проверять статус колеса перед уведомлением |
| `NOTIFY_RETRY_WINDOW_MINUTES` | `180` | Повторять недоставленные уведомления не старше этого возраста, мин |
| `NOTIFY_RETRY_MAX_PER_CYCLE` | `10` | Максимум повторных отправок за один цикл |
| `STALE_COMMAND_SECONDS` | `120` | Старые команды подтверждаются, но не выполняются (защита от бэклога) |
| `CHANNEL_FAIL_THRESHOLD` | `5` | Уведомление после N неудачных циклов канала |
| `CHANNEL_EMPTY_THRESHOLD` | `3` | Уведомление после N циклов, в которых страница канала открылась, но постов в ней не нашлось |
| `ALERT_ON_FIRST_RUN` | `false` | Слать находки первого прохода |
| `TWITCH_ENABLED` | `true` | Мониторинг Twitch-чатов |
| `WHEELSPARSER_TWITCH_CHANNELS` | пусто | Twitch-каналы через запятую, только при первом запуске (аналог `WHEELSPARSER_CHANNELS`) |
| `TWITCH_BOTS` | nightbot, streamelements, moobot, fossabot, wizebot, streamlabs | Логины ботов, чьи ссылки принимаются без бейджа мода |
| `TWITCH_IDLE_TIMEOUT_SECONDS` | `360` | Без данных от IRC дольше — соединение считается зависшим, переподключение |
| `TWITCH_QUEUE_MAXSIZE` | `500` | Очередь сообщений со ссылками между IRC-потоком и обработчиком |
| `USE_COLORS` | `true` | Цвет в консоли |
| `USE_ICONS` | `true` | Эмодзи-значки в логе |

В `cmd.exe` эмодзи квадратами → `USE_ICONS=false` (метки `[OK]`, `[!]`, `[NEW]`) или Windows Terminal. В `parser.log` цветовые коды не пишутся.

## Файлы

Правятся руками: `.env` (создайте сами), `channels.txt`, `twitch_channels.txt`, `keywords.txt` — списки-источники правды, создаются автоматически при первом запуске и меняются командами бота.

Машинное состояние — в `data/` (переопределяется `WHEELSPARSER_DATA_DIR`, при апгрейде переносится из корня само): `wheels.db` (история находок, SQLite), `seen_ids.json` (обработанные сообщения), `bot_state.json` (offset бота — команды не выполняются повторно после рестарта), `removed_wheels.json` (скрытые из `/active`), `pending_expired.json` (ссылки, ошибочно признанные завершившимися и ждущие перепроверки — переживает рестарт, иначе такая находка терялась бы навсегда), `parser.log` (с ротацией, токен бота маскируется).

Запись истории: URL, время обнаружения, канал и источник (`telegram`/`twitch`), ID и URL сообщения, фрагмент текста, статус колеса, результат отправки.

**История в SQLite.** До версии 3.x история лежала в `freebets.json`: файл целиком переписывался в конце каждого цикла с находкой и целиком перечитывался на каждую команду бота. Теперь новая находка — это один `INSERT`, а `/status`, `/wheels`, `/active` и `/top` — запросы с `WHERE` и `GROUP BY` по индексам. Ставить ничего не нужно: `sqlite3` входит в стандартную библиотеку Python. При первом запуске новой версии `freebets.json` переносится в `wheels.db` автоматически и переименовывается в `freebets.json.migrated` — повторный импорт не выполняется. Режим WAL: чтения бота не блокируют запись парсера.

## Как это работает

**Время.** Все даты и счётчики — по Москве (UTC+3, без летнего времени), независимо от таймзоны сервера: `found_at`, `/status`, окно `/wheels`, суточный сброс `/active` в 00:00 МСК.

**URL.** Единая каноническая форма везде (извлечение, дедупликация, `/active`, кэши): без query-параметров и завершающего `/`, домен в нижнем регистре без `www`. Разные хвосты одной ссылки схлопываются в одну запись. Схема (`https://`) необязательна на входе: Twitch-боты (nightbot, StreamElements и т.п.) нередко режут её в сообщениях чата — такая ссылка находится и достраивается до `https://`, чтобы совпасть с тем же колесом из Telegram.

**Дедупликация.** Повтор того же URL подавляется на `REALERT_COOLDOWN_MINUTES`, потом уведомление уходит снова: колёса живут на постоянных адресах, и тот же URL может означать новый запуск. Кулдаун общий для Telegram и Twitch — дубль из двух источников не рассылается.

**Expired-кэш.** Ссылка, признанная завершившейся (`expired`), на `EXPIRED_CACHE_TTL_SECONDS` кэшируется отдельно от `REALERT_COOLDOWN_MINUTES` — короткий TTL нужен только чтобы не бить по API BetBoom за один и тот же «хвост» в нескольких постах подряд, а не для подавления повторов (кулдаун на `expired` не ставится специально). Перепроверка ранее пропущенных ссылок (см. «Доставка» ниже) всегда обходит этот кэш.

**Доставка.** Пост разбирается по хэшу содержимого один раз, поэтому неудачная отправка (`notified: false`) повторяется в начале следующих циклов, пока не дойдёт (`NOTIFY_RETRY_WINDOW_MINUTES`, `NOTIFY_RETRY_MAX_PER_CYCLE`); переживает рестарт. Ретраятся обе находки: ссылки на колёса и посты с ключевыми словами (последние лежат в истории без поля `url` и в `/wheels`, `/status`, `/active` не показываются). Записи с неизвестным статусом доставки не повторяются — `sendMessage` не идемпотентен. Кандидаты на повтор сортируются не только по времени находки, но и по числу уже сделанных попыток: без этого запись, которая не доставляется раз за разом, как самая старая монополизировала бы весь `NOTIFY_RETRY_MAX_PER_CYCLE` каждый цикл, и более свежие находки не получили бы ни одной попытки до истечения окна. Ссылка, которую API BetBoom на момент находки посчитал уже завершившейся, тоже не теряется навсегда: пост уже помечен «увиденным», и правка поста её не перепроверит, поэтому такая ссылка перепроверяется на каждом следующем цикле в течение того же `NOTIFY_RETRY_WINDOW_MINUTES` — если статус окажется активным (ошибка API или неточный расчёт дедлайна), уведомление уйдёт задним числом. Не переживает рестарт: список ждущих перепроверки живёт в памяти.

**Дедлайн.** Конец розыгрыша считается сам (`start_dttm` + `duration_min` из API BetBoom, флаг `is_ended` запаздывает) и показывается в уведомлении и `/active`: «до 21:40 (осталось 12 мин)». Остаток пересчитывается в момент отправки, поэтому верен и в повторной попытке. Срок неизвестен (сбой API или колесо без времени старта) — строка не показывается.

**Twitch.** Подключение анонимное (`irc.chat.twitch.tv:6697`, SSL, ник `justinfan*`). Ключевые слова в чатах не ищутся — зрители пишут «колесо» постоянно. Уведомление уходит сразу, не дожидаясь цикла Telegram; записи попадают в историю с `"source": "twitch"`. Работа разнесена на два потока: `twitch-irc` только читает сокет, `twitch-worker` ходит в API и шлёт уведомления — иначе HTTP-вызов блокирует чтение сокета, ответ на PING опаздывает и Twitch выбрасывает парсер из чата. `/addtwitch` и `/removetwitch` применяются на лету, без перезапуска. У IRC нет истории: сообщения за время простоя парсера не восстанавливаются.

## Живучесть

Что процесс переживает без ручного вмешательства:

| Отказ | Реакция |
|---|---|
| Ошибка внутри цикла парсинга | цикл пропускается, следующий идёт по расписанию |
| Необработанная ошибка в потоке (`parser`, `bot`, `twitch-irc`, `twitch-worker`) | перезапуск потока (пауза 5 → 300 сек), одно уведомление на серию сбоев |
| Обрыв или зависание Twitch IRC | переподключение с backoff 5–120 сек, вотчдог `TWITCH_IDLE_TIMEOUT_SECONDS` |
| Канал недоступен (404, сеть) | уведомление после `CHANNEL_FAIL_THRESHOLD` циклов |
| Канал открывается, но постов нет | уведомление после `CHANNEL_EMPTY_THRESHOLD` циклов |
| Постов нет разом во всех каналах | одно уведомление «похоже, изменилась вёрстка t.me/s» — иначе отказ невидим: каналы считались бы исправными |
| Второй запущенный экземпляр | не стартует, блокировка lock-файла |

## Структура кода

| Слой | Модули |
|---|---|
| Инфраструктура | `config.py` (настройки, регэкспы, значки), `logging_setup.py`, `timeutils.py` (МСК), `net.py` (HTTP-сессии, по одной на поток), `runtime.py` (`STOP_EVENT`, сигналы, супервизор потоков, lock) |
| Данные | `registry.py` (списки каналов и слов), `storage.py` (JSON-состояние), `urls.py` (канонизация, хэш поста), `keywords.py`, `alerts.py` (кулдаун) |
| Внешние API | `betboom.py` (статус колёс, кэш завершившихся), `telegram_api.py` (отправка) |
| Логика | `parser.py` (обход Telegram, контроль отказов каналов), `twitch.py` (IRC + обработчик), `bot.py` (команды, `getUpdates`), `active_report.py` (`/active`) |
| Запуск | `app.py` — `main()`, потоки под супервизором |

Зависимости направлены сверху вниз, циклов нет. Подробности — в докстрингах модулей.
